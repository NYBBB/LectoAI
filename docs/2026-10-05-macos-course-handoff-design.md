## 0. 一页摘要

### 0.1 做什么，按什么顺序

| 步 | 任务 | 版本（暂定） | 一句话 | 解决的事 |
|---|---|---|---|---|
| 一 | C1 | 0.5.0 | 每堂课知道自己是哪门课、交到哪儿 | 四门课只有一个文件夹；回看旧课被导进“当前”文件夹；同一堂课导出两套；冲突不出声；最后几段没交出去 |
| 二 | G1 | 0.5.1 | 别丢课 | 音源选错录了一堂静音；合盖后忘点继续；该上课没在录；崩溃后同一次课变成两条 |
| 三 | H1 | 0.6.0 | 交接时把话说清楚 | 导出物里没有日期、墙钟、暂停位置；外部 Agent 分不清残缺课与短课；不知道文件还会不会变 |

顺序的理由：第一步去掉每天的摩擦，并修掉会污染课程仓库的问题；它产生的课程与上课时间记录，第二步的“到点提醒”“记住音源”要用；第二步落盘的暂停原因，第三步的对账要用。

### 0.2 不在这三步里

暂缓与不做的清单见 §7。重点：不做“离席叫回”、不做手机 App、不让外部 Agent 开停录音、不在 App 里建服务或 Agent 平台。

### 0.3 沿用的原则，另加四条

沿用主设计 §0.2 的六条原则。本设计另加：

1. **课程不是开始的前提，也没有任何前置设置。** 没有课程照样点一下就上课。课程在第一次下课归档时就地建立，名称和上课时间先自动填好，用户只需要确认；上课时间之后由 App 从上课记录里自己积累，不用填课表。拿不准是哪门课时，下课再问，不在上课前问。（用户 2026-10-05 明确：不要一上来就让人做一通设置。）
2. **顺利时界面不多出任何东西。** 只有没录到、没交到、交错了，才出现提示。
3. **提示不出声。** 课堂场合只用界面提示和无声的系统横幅通知。
4. **只写 App 确知的事实。** 对账写墙钟、暂停、缺口这些确知的事，不写猜测；没有标记不代表原文准确，要明说。

## 1. 第一步（C1，0.5.0）：课程

### 1.1 概念

**课程** = 名称 + 课程文件夹。上课时间不用填：每次有课堂归到这门课，App 就记下它是星期几、几点上的，之后按这些记录认课。文件命名模板和学期第一周仍是全局设置，所有课程共用。

没有任何前置设置。课程在第一次下课归档时就地建立：选一次文件夹，名称和上课时间已经填好，点“完成”。设置里的课程页只用来事后修改。

每堂课最多归到一门课。归了课的课堂，第一次交接时把“交到哪门课、文件名开头、时区”固定下来，之后的更新一直沿用，不再随标题、模板、系统时区变化。

名词统一：把文件放进课程文件夹叫**交接**（界面动词用“交到”）；导出面板仍叫“导出”，因为它还能导出到一次性位置。

#### 就地新建课程

课程不是在设置里建的，而是在第一次用到的时候建：下课横幅上的“放进课程文件夹…”或“新课程…”。

第一步，点按钮后直接弹出系统的文件夹选择面板，提示语是“选择这门课放课堂文件的文件夹”。这一步省不掉：沙盒里的 App 只能写用户亲自选过的文件夹。

第二步，选完后横幅下方展开一张确认卡，内容都已填好：

```
新课程
  名称       [ CS 3214            ]     从文件夹路径里认出来的，可改
  文件夹     课堂转录
  上课时间   周二 09:30 左右              就是刚上完的这堂课，以后按它认课
                                              [取消] [完成]
```

第三步，点“完成”或按回车：建好课程，把这堂课归进去并交接，横幅变成“已交到 CS 3214”。

- 名称从路径里由近到远找像课程代码的一段（如 `CS3214`、`CS 3214`），找不到就用文件夹名。
- 上课时间不是输入框，只是告诉用户记下了什么；它来自这堂课实际的开始时刻和时长。
- 时区取当前系统时区，不问。
- 全程是：点一下、选文件夹、点完成。同一门课以后不会再出现这张卡。

### 1.3 规则

**认课**（开始页显示时每分钟算一次，开始录音时再算一次）。每门课有一组“上过课的时间”（星期几、开始时刻、时长，见下一条）。“吻合”指：星期几相同，并且现在落在那次开始前 25 分钟到结束前 10 分钟之间。

1. 用户在开始页手动选了，用它（依据：手动）。
2. 否则，恰好一门课有吻合的时间段，并且这个时间段靠得住：用它（依据：以往时间），下课直接交。“靠得住”指最近 5 周内上过，并且满足其一：这个时间段上过至少两次；或上过一次，而这门课在别的日子的同一时刻（前后 25 分钟内）也上过课。
3. 否则，下面两种情况只给建议（依据：猜测），下课时请用户点一下确认：
   - 恰好一门课有吻合的时间段，但还不够靠得住（只上过一次且没有旁证，或已经超过 5 周没上）；
   - 没有课吻合到星期几，但恰好一门课在别的日子的这个时刻（前后 25 分钟内）上过课。
4. 否则不猜，下课再问。

从工具栏“开始新课堂”或菜单栏“开始听课”开始的课，没有第 1 条，其余相同。导入的录音不认课，导入结束时按“要问”处理。

**记录上课时间**：课堂归到一门课时（下课选的、确认建议、新建课程、手动改的都算），按课程的时区记下星期几、开始时刻和时长。同一星期几、开始时刻相差 30 分钟以内的并成一条，次数加一，时刻取平均。课堂改到别的课、或被移到废纸篓时，从原来那门课里减掉这一次。导入的录音不记，不到 10 分钟的课堂也不记。

一门每周两次的课，从零开始是这样的：第一堂下课时就地建课；第二堂（另一个星期几）下课时点一下确认；第三堂起自动。

**下课时**：依据是以往时间或手动的，自动交接打开时直接交；依据是猜测的，横幅把建议的那门课排在第一个并高亮；没有依据的，横幅列出已有课程和“新课程…”。

**固定文件名开头**（第一次交到某门课时算一次，写进这堂课的记录）：

1. 按全局模板算出开头。日期部分用这堂课的上课日期（导入的录音用录制日期，见 §1.6），按课程的时区。
2. 标题仍是默认的日期标题时，`{title}` 用课程名代替，不等 AI 起名。（一次性导出到其他位置不走这条，命名与以前相同。）
3. 检查课程文件夹里有没有同样开头的文件：
   - 没有：就用它。
   - 有，而且内容和这堂课要写的完全相同（重装、换机后重新交接）：认领这些文件，不重写。
   - 有，但不是这堂课的：依次试“开头 (2)”“开头 (3)”……整套文件用同一个序号。
4. 之后这堂课的所有自动更新都用这个开头。只有在导出面板里手动改名才会换，并且另存一套（与现在相同）。

**自动更新只走固定身份**：没有固定身份的课堂（没归课，或从没交过）不会被任何自动动作交出去。回看旧课时记笔记、问 AI，只会更新它自己当初交到的那门课。

**被改过的文件**：只有“我们写的文件之后被外部改了，而我们又有新内容”才另存，名字为“原名 (LectoAI 更新 MMdd-HHmm).扩展名”，并在横幅、侧栏、导出面板里说明。不同课堂撞名不再走这条路（上面第 3 步已处理）。

**被移走的文件不复活**：上次交出的文件现在不在了（被归档、改名或删除），自动更新跳过它并记一笔；只有在导出面板手动导出才会重新生成。

**失败**：把原因记进这堂课的记录，横幅和侧栏显示；下次启动、下一堂课结束、手动点“重试”时再试。课程文件夹授权标记为过期但仍可访问时，自动刷新授权，不再直接报错。

### 1.4 交接时机

1. 点结束后，本机保存完成，**立刻交一次**（原文、已有译文、笔记先到，合盖就走也来得及）。
2. 收尾的四件事（补译、AI 段落翻译、总结最后一段、最后一次纪要）全部结束后，**自动补交一次**。现在总结续写和 AI 段落翻译完成时不触发导出，这一步补上。
3. 之后笔记、问答、纪要有变化，照常更新（已有行为）。
4. 开始下一堂课、退出 App 时，上一堂没做完的收尾照旧会被打断；这堂课再次打开时，横幅显示“还有 N 段没翻译完”和按钮“补完”。

写文件不占用资料库的串行队列：先在队列里渲染出文件内容和计划，再到队列外写盘，写完把结果记回去。这样慢速的课程文件夹不会拖住下一堂课的录音。

### 1.5 迁移

- 首次启动 0.5.0：已有“课程文件夹”而没有课程时，自动建一门课：文件夹沿用，名称按 §1.2 的规则从路径推断，时区取系统时区。不弹任何设置界面。
- “自动交接”开关沿用原来的值；从未设置过的，有课程后默认打开。
- **用已有课堂学上课时间**：每当一门课建好（包括上面自动建的），App 把还没归课的旧课堂对一遍——本机留有“这堂课当初交到过这个文件夹”的账本的，就归到这门课、按当初的名字补上固定身份，并记下它的上课时间。已经用了几周的人，建完课程就有了时间记录，下一堂课直接自动。只比对本机的账本文件名，不读课程文件夹里的内容；对不上的旧课堂保持未归课，不自动交接，可以手动归。
- 导出面板里起过的名字（`exportNames`）在固定身份时成为文件名开头。
- 旧键保留不删，回退到 0.4.x 仍能按原方式导出。注意：新版本写入的课堂记录含旧版本不认识的事件，旧版本会把这些课堂报为“无法读取”（原始文件保留）。

```swift
/// 一门课上过课的一个时间段，由归课记录累计而来，不是用户填的。
public struct Meeting: Codable, Sendable, Equatable {
    public var weekday: Int          // 1=周日 … 7=周六，按课程时区
    public var start: Int            // 开始录音时是当天第几分钟（多次取平均）
    public var minutes: Int          // 时长（多次取平均）
    public var count: Int            // 这个时间段上过几次
    public var last: Date            // 最近一次上课
}
public struct Course: Identifiable, Codable, Sendable, Equatable {
    public var id: UUID
    public var name: String
    public var folderBookmark: Data?   // 没有则只归类、不交接
    public var folderName: String
    public var timeZoneID: String      // 上课地时区
    public var meetings: [Meeting]     // 自动记录的上课时间
    public var lessonCount: Int        // 归过几堂课
    public var createdAt: Date         // 建课时间；此前录的课堂不催归档
    public var lastUsed: Date?         // 最近一次归课，用于按钮排序
    public var remind: Bool            // 到点没录提醒（G1），默认开
    public var lastSourceSystem: Bool? // 上次用的音源（G1）
    public var archived: Bool
}
public struct CourseBook: Codable, Sendable, Equatable {
    public enum Confidence: Sendable { case known, guess }
    public var courses: [Course]
    /// 按以往上课时间认课；两门课都吻合时返回 nil。
    public func suggest(at date: Date) -> (course: Course, confidence: Confidence)?
    /// 课堂归到课程、从课程移走时更新上课时间记录。
    public mutating func learn(courseID: UUID, start: Date, minutes: Int)
    public mutating func forget(courseID: UUID, start: Date)
    /// 从文件夹路径推断课程名。
    public static func suggestedName(for folder: URL) -> String
}
```

### 1.7 验收

自动化（核心包测试）：
- 认课：归过两堂课后，同一星期几同一时刻自动认出；只归过一堂或只对上时刻时只给建议；两门课都吻合时不猜；跨时区（系统在东八区、课程在美东）。
- 记录上课时间：相近的并成一条并累计次数；课堂改到别的课后从原课程里减掉；导入的录音不记。
- 建课后用旧账本认领旧课堂：对得上的归课并记下时间，对不上的不动。
- 固定身份：交接后改标题、改模板、改系统时区，再更新，文件名不变、不出第二套。
- 撞名：同一天两堂课得到“(2)”；文件夹里已有外来同名文件得到“(2)”；内容相同的被认领、不重写。
- 冲突：外部改过的文件另存并出现在结果里；被移走的文件不重建。
- 回看旧课记笔记：只更新它自己那门课；没有固定身份的旧课不被交出。
- 迁移：单一课程文件夹变成一门课；旧课堂能按旧账本补上固定身份。

### 1.8 审核后补充的边界与体验细节（2026-10-05）

落地前对方案做了一次审核，补充如下，均属 C1 范围。

边界：
- **太短的课堂不自动交接。** 不到 2 分钟或没有任何文字的课堂只保存在本机，横幅给“放进课程文件夹…”，不自动写文件，也不记上课时间。
- **选到的文件夹已经属于某门课。** 不新建课程，直接归到那门课，并提示“这个文件夹已经是‘CS 3214’的”。
- **升级后不催旧课堂。** 侧栏“还没选课程”的图标和再次出现的询问横幅，只对第一门课建立之后录的课堂生效。
- **自动交接的默认值。** 全新用户有了课程后默认打开；升级前设过文件夹但从没打开过自动导出的，保持关闭。
- **同一堂课的交接串行执行。** 1.5 秒内的连续触发合并为一次；写文件在资料库队列之外进行。
- **失败不刷屏。** 同一原因的连续失败只记一条。
- **撞名只看本 App 的文件。** 课程文件夹里只有“开头 + 本 App 的固定文件名”才算同名；外部 Agent 写的“… 整理 - 主题.md”不算。
- **认课结果在开始录音后不再自动变化**，只有用户手动改才变。
- **课程被删除或收起后**，归到它的课堂保留课程名，不再自动更新，侧栏不报警。
- **演示与测试模式不读写真实的课程设置**（Debug 与 DMG 共用偏好）。

体验：
- **询问横幅不绑定回车键**，避免误归课；确认卡绑定回车，打开时名称已全选，直接打字即可改名。
- **课程按钮按最近使用排序**，有建议的排第一并高亮；超过 5 门时其余收进“更多”菜单；窗口窄时按钮自动换行，不挤掉正文。
- **确认卡显示文件夹的最后三级路径**（如 CS3214 › raw › 课堂转录），让人确认选对了地方。
- **状态切换的动效**：横幅内容淡入淡出，交接完成时对勾弹一下；按钮组出现时有轻微位移。全部跟随系统“减弱动态效果”。
- **交接进行中**横幅显示“正在交到‘CS 3214’…”和小转圈，完成后原位换成结果，不另弹提示。
- **改课堂标题的说明**改为：已经交接过的课堂，文件名不变。
- **读屏与键盘**：课程按钮、确认卡字段有可访问标签；所有新控件可用 Tab 到达。

待用户验证（真实课堂）：
- 从零开始用两周，全程不打开设置：每门课的第一堂下课时就地建课（点一下、选文件夹、点完成）；第二堂只需点一下确认；之后零点击交到对的文件夹。
- 下课立刻合盖：回来后文件已在课程文件夹，且收尾后的内容在唤醒后补上。
- 故意选错课再改：旧文件被选中、新文件到位。

### 1.9 实现与审查后的修订（2026-10-05，0.5.0）

C1 已按本节以上内容实现。实现后做了一次独立代码审查，下面是与前文不同或前文没写到的地方，以这里为准。

- **所有交接排成一队**（不只是同一堂课串行）：两堂课不会同时抢到同一个文件名开头。定开头时除了看课程文件夹里的文件，还避开这门课里别的课堂已经定下的开头（它们的文件可能已被归档走）。
- **第一次交接只在这些时刻发生**：下课、归课、重试、启动补交、用户主动导出。翻译、纪要、笔记这些后续变化只更新已经交过的课堂——太短的课堂、自动交接关着时结束的课堂不会被它们顺带交出去。
- **文件被外部改过、而我们没有新内容时什么都不做**（不另存副本）。有新内容才另存“原名 (LectoAI 更新 月日-时分)”。
- **冲突提示会一直留到你看过**（点“查看”或关掉横幅），期间侧栏有橙色标记；“查看”会在 Finder 里同时选中副本和被改过的原文件。
- **文字先登记，录音单独登记**：录音合成失败不会丢掉已经定下的文件名开头；写到一半出错时已写好的文件照常入账，重试不会产生副本。
- **被移走的录音和文字一样**，自动更新不放回，手动导出才重新生成。
- **退出前等交接做完，最多等 8 秒**；来不及的由下次启动补交（近三天、已归课的课堂逐个核对，内容没变不写文件）。
- **开始页手动选的课程 3 小时内有效**：选了没上课，不会把第二天的课归过去。
- **导出面板只预选靠得住的课程**；只是“猜的”不预选，免得一按回车就归错。
- **同一天同一时段的多段录音只算一次上课**（断线重录不会让一门只上过一次的课变成“靠得住”）。
- **认领旧课堂每次启动和每次建课后都做一遍**（幂等），不是只在迁移时做一次。
- 没做：单次交接的超时（文件夹所在的盘卡住时后面的交接会排队）；没做完的收尾没有“补完”横幅；开始页不提前提示课程文件夹失效（要到交接失败才提示）；上课时间不提供逐条删除（改归课堂后自动重新统计）。

## 2. 第二步（G1，0.5.1）：别丢课

### 2.1 开录自检

开始录音后的头一段时间检查两件事。阈值用原始分贝，不用界面电平条的归一化值（安静的教室也可能是 0 格）。

| 检查 | 条件 | 提示 |
|---|---|---|
| 完全没有输入 | 麦克风：10 秒内一直低于 −80 dBFS。电脑声音：20 秒内一直是静音 | 橙色横幅 + 小窗状态变橙 + 菜单栏图标变化；App 不在前台且小窗没开时发一条无声的系统通知 |
| 有声音没文字 | 45 秒内累计 5 秒以上高于 −50 dBFS，却没有任何识别文字 | 蓝色横幅，不发通知 |

文案：

| 场景 | 正文 | 副文 | 按钮 |
|---|---|---|---|
| 麦克风没输入 | 没有收到麦克风的声音。 | 检查麦克风是否被静音，或被别的设备占用。 | 改用电脑声音 |
| 电脑声音没输入 | 电脑没有在播放声音。 | 现场上课请改用麦克风。 | 改用麦克风 |
| 有声音没文字 | 有声音，但还没有识别出文字。 | 老师还没开始讲的话可以忽略。 | 知道了 |

“改用…”一步完成暂停、换音源、继续，仍是同一堂课。条件消失（来了声音或文字）时提示自动收起。

### 2.2 课中状态

工具栏的录音状态和小窗左上角的状态同步变化：

```
正常        ● 12:03 ▂▄▆      [暂停] [结束]
没有输入    ⚠ 没有声音 12:03  [暂停] [结束]
网课安静    ● 12:03 已安静 1 分钟
```

- **麦克风**：录到过声音之后，连续 10 秒低于 −80 dBFS，按“完全没有输入”处理（麦克风被拔掉、被静音）。教室里的正常安静高于这个值，不会触发。
- **电脑声音**：静音是常态（没人说话就是 0），所以不报错。连续安静满 60 秒，电平条的位置换成灰字“已安静 N 分钟”，有声音就恢复。25 秒以上的安静区间记进这堂课的记录，只记录、不提示——留给以后判断“安静提示”值不值得做（§7）。
- **暂停着**：
  - 不是你点的暂停（设备切换没续上、唤醒后没自动继续）：App 不在前台时立刻发通知“这堂课暂停了：原因”，按钮“继续”“结束并保存”。
  - 你点的暂停：满 10 分钟发一次“这堂课已经暂停 10 分钟”，同样两个按钮；只发一次。

### 2.3 合盖与唤醒

- 暂停时把原因写进记录（手动、合上屏幕、音频设备变化、换音源、退出），现在只有界面上一句话。
- 监听唤醒。唤醒时如果当前课堂是因睡眠而暂停的：
  - 睡了不到 3 分钟，或现在仍在这门课以往的上课时间内：2 秒后自动继续，底部提示“已自动继续录音”，中间没录到的时长记为“合上屏幕”。
  - 否则不自动继续（避免回到宿舍开盖就开始录），横幅：“合上屏幕时已暂停（14:05）。”按钮“继续”“结束并保存”。
- 唤醒时如果当前课堂有没做完的收尾，接着做（配合 §1.4）。

### 2.4 课程记住音源；到点没录提醒

- 每门课记住上次用的是麦克风还是电脑声音。开始页选中（或按以往时间认出）这门课时，音源跟着切。线下课和网课混着上时，不用再记得改。
- 到点没录提醒不需要逐门课设置：用户在开始页开启“提醒”（§2.7，点一下）之后，凡是同一时间上过至少两次的课都会提醒。某门课不想被提醒，在它的编辑面板里关掉“上课时间到了还没开始录就提醒我”。
  - 上课 3 分钟后还没有在录：通知“CS 3214 已经开始 3 分钟，还没在录”，按钮“开始听课”“今天没课”。
  - 点“开始听课”：打开 App，用这门课和它记住的音源直接开始。
  - 实现：每次启动、上课时间记录变化、开始录音时，为未来 14 天的每个上课时间各排一条一次性的本地通知；在该时间段内开始了录音就撤掉当天那条。App 没开时通知照样会到。
  - 收起的课程不提醒。

### 2.5 中断的课接着录；退出确认

- 启动时发现上次异常中断的课堂（现在只能打开看）：如果是今天的课，开始页横幅加按钮“接着录”；打开这堂课时横幅同样有“接着录这堂课”。接着录仍是同一堂课、同一套文件。工具栏的主按钮仍是“开始新课堂”，避免误把新课接到旧课后面。
- 正在录音时退出：先确认“正在录音。退出会结束并保存这堂课。”按钮“结束并退出”“取消”。暂停状态下退出不确认，行为与现在相同。

### 2.6 字幕里的暂停标记

回看时，在暂停发生的位置插一行居中的细字（段落本来就在这里断开）：

```
        ⏸  这里暂停了 5 分 23 秒 · 合上屏幕 · 09:58–10:04
```

换音频设备造成的约 1 秒空白用更小的字：“换了音频设备，约 1 秒没录到”。小窗不显示。

### 2.7 通知

- 开始页“准备情况”加一行“提醒  可选”：“录音出问题、该上课没在录时提醒你”，按钮“开启”。已开启显示对勾；在系统设置里被关闭时显示“已在系统设置中关闭”和按钮“打开系统设置”。
- 所有通知不带声音，用普通级别。Mac 开着专注模式时会被系统压下，所以通知只是补充，界面提示才是主通道。
- 不需要新增沙盒权限，只需要用户授权。

### 2.8 数据与实现要点

- 管线的电平回报同时带上原始分贝。
- 新事件：`pauseReason(String)`（紧挨着暂停、中断、结束的状态事件之前追加）、`quiet(start, end)`。
- 时间线由状态事件推出：资料库在追加和重放日志时把每条事件的墙钟时间交给状态归并，生成 `Lesson.timeline`（开始、暂停、继续、结束，各带录音时间、墙钟时间、原因、音源）。旧课堂的日志里本来就有每条事件的墙钟，重放后同样得到时间线，只是没有原因。导入的课堂标为“无墙钟”。
- `canResume` 扩展到“今天中断的课堂”；`AudioRecovery.reconcile` 已经会补登音频块，接着录时从现有时长续上。
- 新增一个很薄的通知封装（申请权限、排期、撤销、处理按钮）。

## 7. 暂缓与不做

| 事项 | 结论 | 什么时候再看 |
|---|---|---|
| 给外部 Agent 的课中只读入口（现场目录） | 暂缓 | 先做零代码探针：用脚本按真实节奏把一份旧转录写成追加文件，看 Agent 能否答出带时间的内容并在停写后指出数据过期；并确认课上确实会去问外部 Agent |
| 安静提示（网课里“已安静 25 秒”主动提示） | 暂缓 | G1 只记录安静区间；攒两周数据，看这些区间里互动或故障的占比 |
| “离开一下”标记、课间回来提醒 | 暂缓 | 确认寒假那门课是同步上课、并且允许之后 |
| 只采集会议 App 的声音 | 暂缓 | 先做探针；浏览器上课是多进程 |
| 没做完的收尾在后台自动补做 | 暂缓 | C1 先提供“补完”按钮；连堂课多、手动补嫌烦时再做 |
| 独立的 JSON 清单、MCP 封装 | 暂缓 | H1 的验证表明外部 Agent 需要更多结构时 |
| 按课程覆盖命名模板 | 暂缓 | 有一门课的命名习惯确实不同的时候 |
| 手动填写课表 | 不做 | 上课时间由归课记录自动积累；记错了就把那堂课改到别的课 |
| 选一次学期文件夹，一次认出里面所有课程 | 暂缓 | 逐门课在下课时选文件夹仍嫌麻烦的时候（只能认出已经放有转录文件的子文件夹） |
| “离席叫回”、名字或关键词监听、来电升级 | 不做 | — |
| 手机 App、设备间实时接力 | 不做 | 手机录音照旧放进课程工作区，由外部 Agent 按墙钟补洞 |
| 外部 Agent 开始、暂停、结束录音 | 不做 | — |
| App 内合并课堂、多轨编辑；回执或收件箱协议 | 不做 | — |
| 截屏或读屏监视会议软件；App 内置服务或 Agent 平台 | 不做 | — |
